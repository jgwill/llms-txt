## Platform Overview

The Medicine Wheel Developer Suite is a layered npm package ecosystem grounded in **Two-Eyed Seeing**. It bridges the Engineer-world's precision with the Ceremony-world's relational accountability. `@medicine-wheel/ontology-core` serves as the platform nucleus, defining the fundamental beings (Nodes, Relations, Ceremonies) that all other packages interact with.

Full documentation: `https://docs.medicine-wheel.jgwill.com/`

> **Naming migration (at v0.3.0)**: Packages were renamed from the flat `medicine-wheel-*` form to the scoped `@medicine-wheel/*` form. The legacy `medicine-wheel-ontology-core` (≤0.2.2) is superseded by `@medicine-wheel/ontology-core`. All library packages are published together in lockstep (currently **0.5.5**); the MCP server (`@medicine-wheel/mcp`) is versioned independently (currently **4.5.5**).

## 1. Orientation Layer
*The question asked before an instrument is chosen.*

Two situations look identical under pressure and are not: something worked and stopped (a fire — there is a prior state to restore), and something has never existed and is wanted (a creating act — there is no baseline to close toward). Using the wrong instrument is how rigorous work goes in circles. This layer sits **below** ontology-core and depends on nothing, so the routing question carries no obligation to the instruments it routes to.

### @medicine-wheel/creative-orientation
> The orientation question itself: is there a prior state you are restoring? Yes — this is a fire, route to gap analysis. No — you are creating, route to structural tension. Reads the claim the caller supplies; it never inspects the caller's reasoning and never refuses.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/creative-orientation
- **Role**: Routing, not instrumentation. Urgency is not evidence.
- **Key exports**: `readOrientation`, `reorient`, `routeFor`, `worthSaying`, `ADVANCING_MARKERS`, `ELIMINATION_MARKERS`.
- **Dependencies**: none.

### @medicine-wheel/gap-analysis
> Problem-solving built properly for the case where it genuinely applies — something worked and stopped. Evidenced baseline, observation, difference, verifiable elimination steps. Root cause, incidents, regressions, troubleshooting.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/gap-analysis
- **Role**: The correct instrument for a fire. The baseline requirement is what separates a fire from a creating act.
- **Key exports**: `openGapAnalysis`, `addStep`, `markDone`, `isClosed`, `doorAdvice`.

### @medicine-wheel/creative-problem-solving
> A signpost, not a door — it holds no logic of its own and never will. Carries the routing question and re-exports `@medicine-wheel/creative-orientation`.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/creative-problem-solving
- **Role**: The door people arrive at, which sends them one of two ways.
- **Key exports**: `THE_QUESTION`, plus the full creative-orientation surface.

### @medicine-wheel/brainstorming
> Idea into committed design through approval gates a human holds. Every outcome it emits — including its own multiple-choice questions — passes the orientation check before it is spoken.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/brainstorming
- **Role**: Ideation, requirements gathering, and design review under human-held gates.
- **Key exports**: `openSession`, `advance`, `ask`, `answer`, `checkEmission`, `PHASE_ORDER`, `GATED_PHASES`.

## 2. Foundational Layer
*The soil and the roots.*

### @medicine-wheel/ontology-core
> Platform nucleus: TypeScript types, RDF vocabulary, Zod schemas, Wilson alignment scoring, and OCAP tracking. Relationships are first-class beings with ceremony context and obligations.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/ontology-core
- **Role**: Foundational source of truth for all types and constants.
- **Key types**: `RelationalNode`, `Relation`, `Direction`, `OCAPFlags`, `WilsonAlignment`, `AccountabilityTracking`.

### @medicine-wheel/data-store
> Shared Redis persistence layer: Provides unified access to relational memory (Nodes, Edges, Ceremonies) and bidirectional session-ceremony linking.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/data-store
- **Role**: Relational memory storage and access.

### @medicine-wheel/storage-provider
> Abstract storage layer: Pluggable backend selection (JSONL today, Neon/Postgres, future Redis) behind a single `createProvider()` seam. The long-term provider abstraction for the suite.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/storage-provider
- **Role**: Backend-agnostic persistence abstraction.

### @medicine-wheel/data-store-postgres
> PostgreSQL/Neon scaffold: Shared `pg` Pool helper keyed by connection options, typed against `ontology-core` records, with opt-in SSL. A focused Postgres seam (not the primary backend-selection surface — see `storage-provider`).
- **npm**: https://www.npmjs.com/package/@medicine-wheel/data-store-postgres
- **Role**: Postgres/Neon backend scaffold.

### @medicine-wheel/infra
> Typed infrastructure facets: hosts, tenants, services, and port bindings keyed by relational node id — a home for the machine specifics (`port`, `unit`, `linger`) that otherwise leak into `metadata: Record<string, unknown>`. Port-conflict detection runs over declared ∪ observed state, so an undocumented binding still collides with a declared one.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/infra
- **Role**: Infrastructure as facets over the existing ontology. The closed `NodeType` union is reused, never widened.
- **Key exports**: `detectPortConflicts`, `FACET_NODE_TYPES`, `HostFacetSchema`, `TenantFacetSchema`, `ServiceFacetSchema`, `PortBindingSchema`, `PortConflictSchema`.

## Architecture Flow

```
0. ORIENTATION ──▶ 1. INTENTION (EAST)  ──▶ 2. RESEARCH (SOUTH) ──▶ 3. VALIDATION (WEST) ──▶ 4. ACTION (NORTH)
   creative-           prompt-decomposition     relational-query        community-review        narrative-engine
   orientation         fire-keeper              relational-index        consent-lifecycle       data-store
   gap-analysis                                 importance-unit         transformation-tracker
   brainstorming
```

Orientation is step 0, not step 1: it decides whether the wheel is the right
instrument at all. A situation with a real prior state to restore belongs to
`gap-analysis`, and routing it into the creative cycle would aim the work at a
list of known failures instead of at the outcome.

## Alignment Principles

- **Relational Accountability**: Every package serves to strengthen the web of relations between researcher, community, land, and spirit.
- **Circular Progression**: Work is not linear but spiral; revisiting a topic (circle depth) is a sacred act of deepening understanding.
- **OCAP® Sovereignty**: Indigenous data sovereignty (Ownership, Control, Access, Possession) is enforced at the code level.
- **Wilson Validity**: Research is validated by its transformative impact on all participants and the health of the resulting relations.
