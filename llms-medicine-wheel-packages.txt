## Platform Overview

The Medicine Wheel Developer Suite is a layered npm package ecosystem grounded in **Two-Eyed Seeing**. It bridges the Engineer-world's precision with the Ceremony-world's relational accountability. `@medicine-wheel/ontology-core` serves as the platform nucleus, defining the fundamental beings (Nodes, Relations, Ceremonies) that all other packages interact with.

Full documentation: `https://docs.medicine-wheel.jgwill.com/`

> **Naming migration (at v0.3.0)**: Packages were renamed from the flat `medicine-wheel-*` form to the scoped `@medicine-wheel/*` form. The legacy `medicine-wheel-ontology-core` (≤0.2.2) is superseded by `@medicine-wheel/ontology-core`. All library packages are published together in lockstep (currently **0.5.3**); the MCP server (`@medicine-wheel/mcp`) is versioned independently (currently **4.5.3**).

## 1. Foundational Layer
*The soil and the roots.*

### @medicine-wheel/ontology-core
> Platform nucleus: TypeScript types, RDF vocabulary, Zod schemas, Wilson alignment scoring, and OCAP tracking. Relationships are first-class beings with ceremony context and obligations.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/ontology-core
- **Role**: Foundational source of truth for all types and constants.
- **Key types**: `RelationalNode`, `Relation`, `Direction`, `OCAPFlags`, `WilsonAlignment`, `AccountabilityTracking`.

### @medicine-wheel/data-store
> Shared Redis persistence layer: Provides unified access to relational memory (Nodes, Edges, Ceremonies) and bidirectional session-ceremony linking.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/data-store
- **Role**: Relational memory storage and access.

### @medicine-wheel/storage-provider
> Abstract storage layer: Pluggable backend selection (JSONL today, Neon/Postgres, future Redis) behind a single `createProvider()` seam. The long-term provider abstraction for the suite.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/storage-provider
- **Role**: Backend-agnostic persistence abstraction.

### @medicine-wheel/data-store-postgres
> PostgreSQL/Neon scaffold: Shared `pg` Pool helper keyed by connection options, typed against `ontology-core` records, with opt-in SSL. A focused Postgres seam (not the primary backend-selection surface — see `storage-provider`).
- **npm**: https://www.npmjs.com/package/@medicine-wheel/data-store-postgres
- **Role**: Postgres/Neon backend scaffold.

## 3. Ceremonial & Governance Layer
*The protocols of relationship.*

- **npm**: https://www.npmjs.com/package/@medicine-wheel/ceremony-protocol

### @medicine-wheel/fire-keeper
> Coordination agent: Tends the ceremony fire, evaluates gating conditions, and issues stop-work orders when relational integrity is violated.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/fire-keeper
- **Role**: Active relational alignment agent.

### @medicine-wheel/community-review
> Validation through consensus: Implements Wilson's vision of Elder review circles and talking circle protocols for artifact validation.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/community-review
- **Role**: Community-based consensus and Elder validation.

### @medicine-wheel/consent-lifecycle
> Living consent: Transforms consent from a boolean checkbox into a living relational obligation with renewal, renegotiation, and cascading effects.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/consent-lifecycle
- **Role**: Relational consent tracking and health monitoring.

### @medicine-wheel/ceremonial-diary
> The participant's voice: Intention, observation, and reflection entries across the Five-Phase ceremonial methodology, with pattern detection, statistics, Markdown export, and optional projection into the chronicle wheel. Persists via `@medicine-wheel/storage-provider`. Came home from Miadi.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/ceremonial-diary
- **Role**: First-person ceremonial journaling and reflection.

### @medicine-wheel/github-ceremony
> Witness in code: Reads GitHub webhook events (issues, PRs, merges, commits) through a ceremonial lens and records them as relational ceremony beads. Pure, framework-free functions over a `@medicine-wheel/storage-provider`. Came home from Miadi.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/github-ceremony
- **Role**: Development activity as relational ceremony.

## 7. Perception & Film Layer
*The eyes and ears of Indigenous film production.*

- **npm**: https://www.npmjs.com/package/@medicine-wheel/perception-layer
- **Role**: Witness raw film-production material as typed perceptual events.

### @medicine-wheel/narrative-cluster
> Edit intelligence: Turns witnessed perceptual events / rushes into thematic clusters, narrative beats, and a Film Edit Brief (EDL markers). Deterministic; consumes `perception-layer` output.
- **npm**: https://www.npmjs.com/package/@medicine-wheel/narrative-cluster
- **Role**: Cluster perception into narrative beats and edit briefs.

## Alignment Principles

- **Relational Accountability**: Every package serves to strengthen the web of relations between researcher, community, land, and spirit.
- **Circular Progression**: Work is not linear but spiral; revisiting a topic (circle depth) is a sacred act of deepening understanding.
- **OCAP® Sovereignty**: Indigenous data sovereignty (Ownership, Control, Access, Possession) is enforced at the code level.
- **Wilson Validity**: Research is validated by its transformative impact on all participants and the health of the resulting relations.
