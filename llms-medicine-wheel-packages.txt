> A TypeScript framework for relational healing, ceremonial inquiry, and Indigenous-aligned software development — grounded in the Four Directions, Wilson's three R's, and OCAP® data sovereignty principles.

**Language:** TypeScript (ES2022, ESM)
**License:** Indigenous Knowledge Stewardship License (IKSL) v1.0, MIT derived
**Status:** experimental alpha — see [ALPHA.md](https://github.com/jgwill/medicine-wheel/blob/main/ALPHA.md); pin exact versions
**Versioning:** the suite moves in lockstep on `0.x`; `@medicine-wheel/mcp` keeps its own MAJOR (`4.x`) and follows the suite's minor and patch

## Packages

31 published packages: the app, 29 libraries, and the MCP server.

- [app](https://github.com/jgwill/medicine-wheel): Medicine Wheel app (`@medicine-wheel/app`) — the Next.js visual layer plus two CLIs: `mwsrv` (starts the server against a `.mw/store`, local or Docker) and `mw` (talks to the running server — status, orientation, directions, node/edge/ceremony/beat ops, charts, validators, skills); installs and runs without `@medicine-wheel/mcp`
- [ontology-core](https://github.com/jgwill/medicine-wheel/blob/main/src/ontology-core): Foundational ontology layer for the Medicine Wheel Developer Suite — unified types, RDF vocabulary, Zod schemas, constants, semantic query helpers grounded in Indigenous relational ontology
- [creative-orientation](https://github.com/jgwill/medicine-wheel/blob/main/src/creative-orientation): The orientation question, asked before the work — is there a prior state you are restoring? Yes routes to gap analysis (a fire); no routes to structural tension (a creating act). Holds the routing signals, not the instruments
- [gap-analysis](https://github.com/jgwill/medicine-wheel/blob/main/src/gap-analysis): Problem-solving built properly for when something worked and stopped — evidenced baseline, observation, difference, verifiable elimination steps. The baseline requirement is what separates a fire from a creating act
- [creative-problem-solving](https://github.com/jgwill/medicine-wheel/blob/main/src/creative-problem-solving): A signpost, not a door — carries the routing question and re-exports `@medicine-wheel/creative-orientation`. Named a prior state? gap-analysis. Named none? structural tension
- [brainstorming](https://github.com/jgwill/medicine-wheel/blob/main/src/brainstorming): Idea into committed design through approval gates a human holds — phased sessions where every emitted outcome, including the tool's own multiple-choice questions, passes the orientation check before it is spoken
- [ceremony-protocol](https://github.com/jgwill/medicine-wheel/blob/main/src/ceremony-protocol): Ceremony lifecycle protocol — manages ceremony state, phase transitions, governance enforcement, and ceremonial review workflows
- [fire-keeper](https://github.com/jgwill/medicine-wheel/blob/main/src/fire-keeper): Fire Keeper coordination agent — tends the ceremony fire, ensures relational integrity through gating conditions, and maintains Wilson alignment as an active agent
- [community-review](https://github.com/jgwill/medicine-wheel/blob/main/src/community-review): Community-based ceremonial review protocol — implements Wilson's validation through Elder review circles, consensus-seeking, and relational accountability assessment
- [community-identity](https://github.com/jgwill/medicine-wheel/blob/main/src/community-identity): Who is in the circle — a person is a `human` node with `metadata.kind: "person"` and a role, a circle is a `circle` node, membership is a `member_of` edge; roles carry a permission map, and tokens and invitation codes stay with the consumer, never on the wheel
- [consent-lifecycle](https://github.com/jgwill/medicine-wheel/blob/main/src/consent-lifecycle): Ongoing relational consent lifecycle — consent as a living relational obligation with lifecycle tracking, renewal, renegotiation, and community-level consent protocols
- [narrative-engine](https://github.com/jgwill/medicine-wheel/blob/main/src/narrative-engine): Beat sequencing, arc validation, cadence patterns, and timeline building for the Medicine Wheel Developer Suite
- [importance-unit](https://github.com/jgwill/medicine-wheel/blob/main/src/importance-unit): ImportanceUnit — the relational unit of knowledge carrying epistemic weight, source dimensions (Land/Dream/Code/Vision), circle depth tracking, and accountability links grounded in Wilson's relational epistemology
- [relational-index](https://github.com/jgwill/medicine-wheel/blob/main/src/relational-index): Four-source epistemic dimensional indexing — Land, Dream, Code, Vision traversal with cross-dimensional mapping and spiral depth metrics
- [transformation-tracker](https://github.com/jgwill/medicine-wheel/blob/main/src/transformation-tracker): Research transformation tracking — Wilson validity criterion: if research doesn't change you, you haven't done it right. Tracks researcher, community, and relational transformation
- [graph-viz](https://github.com/jgwill/medicine-wheel/blob/main/src/graph-viz): Medicine Wheel graph visualization — circular layout with four-direction node positioning, ceremony-aware edges, and OCAP® indicators
- [relational-query](https://github.com/jgwill/medicine-wheel/blob/main/src/relational-query): Query builder, graph traversal, and accountability audit for the Medicine Wheel relational web. Protocol-aware: respects ceremony boundaries and OCAP® compliance during traversal.
- [prompt-decomposition](https://github.com/jgwill/medicine-wheel/blob/main/src/prompt-decomposition): Ontology-enriched prompt decomposition engine for the Medicine Wheel Developer Suite — intent extraction, relational dependency mapping, and ceremony-aware action stacking
- [ui-components](https://github.com/jgwill/medicine-wheel/blob/main/src/ui-components): React UI components for the Medicine Wheel Developer Suite — direction cards, beat timelines, node inspectors, OCAP® badges, and Wilson alignment gauges.
- [client](https://github.com/jgwill/medicine-wheel/blob/main/src/client): Typed HTTP door to a running wheel — nodes, edges, ceremonies, beats and the ceremonial diary, with the wheel's paging honesty (`count`, `total`, `matched`, `truncated`) carried through and fail-fast errors that name the status. No retry; `limit: 'all'` asks for the whole store
- [data-store](https://github.com/jgwill/medicine-wheel/blob/main/src/data-store): Shared Redis data-access layer for the Medicine Wheel Developer Suite — connection management, Node/Edge/Ceremony CRUD, session-ceremony linking, and discovery helpers
- [session-reader](https://github.com/jgwill/medicine-wheel/blob/main/src/session-reader): Session event reader for the Medicine Wheel Developer Suite — JSONL parsing, session summaries, analytics extraction, and search across agent session data
- [storage-provider](https://github.com/jgwill/medicine-wheel/blob/main/src/storage-provider): Abstract storage layer — a unified provider interface over JSONL and Neon/Postgres backends (with a future Redis path), selected at runtime
- [data-store-postgres](https://github.com/jgwill/medicine-wheel/blob/main/src/data-store-postgres): PostgreSQL/Neon provider scaffold — shared pool management and provider-ready storage entrypoints for cloud-backed persistence
- [infra](https://github.com/jgwill/medicine-wheel/blob/main/src/infra): Typed infrastructure facets — hosts, tenants, services, and port bindings as facets keyed by relational node id, with port-conflict detection over declared ∪ observed state; built on ontology-core, reusing the closed `NodeType` union rather than widening it
- [honcho](https://github.com/jgwill/medicine-wheel/blob/main/src/honcho): The wheel's projection into [Honcho](https://honcho.dev), memory that reasons. Beats, ceremonies and diary entries become messages from their speakers; a peer's evolving representation is recalled before they speak again; a derived conclusion returns as a `knowledge` node with `metadata.kind: "memory_projection"`. Zero dependencies, `/v3` only, switched on by `HONCHO_URL`
- [ceremonial-diary](https://github.com/jgwill/medicine-wheel/blob/main/src/ceremonial-diary): Ceremonial Diary — a participant's voice across the Five-Phase ceremonial methodology; intention/observation/reflection entries with pattern detection, statistics, Markdown export, and optional projection into the chronicle wheel; persists via `@medicine-wheel/storage-provider`
- [github-ceremony](https://github.com/jgwill/medicine-wheel/blob/main/src/github-ceremony): GitHub-ceremony processing — witness GitHub webhook events (issues, PRs, merges, commits) through a ceremonial lens and record them as relational ceremony beads; pure, framework-free functions over a `@medicine-wheel/storage-provider`
- [perception-layer](https://github.com/jgwill/medicine-wheel/blob/main/src/perception-layer): Eyes & ears of agent-supported Indigenous film production — witness a belt-device recording / transcript as typed `PerceptualEvent`s and seed a production knowledge graph in ontology-core
- [narrative-cluster](https://github.com/jgwill/medicine-wheel/blob/main/src/narrative-cluster): Narrative Cluster Processor — turn witnessed perceptual events / rushes into thematic clusters, narrative beats, and a Film Edit Brief (EDL markers); deterministic; consumes perception-layer output
- [mcp](https://github.com/jgwill/medicine-wheel/blob/main/mcp): Medicine Wheel MCP Server (`@medicine-wheel/mcp`) — 85 tools across orientation, the ceremony lifecycle, relational CRUD, structural tension, narrative, Four-Directions guidance, inquiry-weaves, plan-perspectives, infrastructure, Honcho memory, and validators; stdio + StreamableHTTP transports

## MCP Server & HTTP API

The `@medicine-wheel/mcp` package exposes 85 tools over two transports:

- **stdio** — `npx @medicine-wheel/mcp` (default; local JSONL store under `.mw/store/`)
- **StreamableHTTP** — `POST /api/mcp` on the running app, JSON-RPC 2.0 with `tools/list` and `tools/call`

Tool families: orientation (3 — the routing question asked before any problem-solving, listed first because list order is scan order), Four Directions (13), validators (4 — Wilson paradigm, OCAP® compliance, Two-Eyed Seeing bridge, accountability), integrations (11) and discovery (11) over nodes/edges/ceremonies/beats/cycles, structural tension (12 — charts, action steps, MMOT), ceremony lifecycle (4), epistemic (2), coordination (3 — fire-keeper status, relational check-back, gate enforcement), governance and transformation (3), reasoning observability (2), inquiry-weaves (3), plan-perspectives (3), infrastructure (7 — hosts, tenants, services, port conflicts, metis holds), and Honcho memory (4 — status, project, recall, project back).

**Server-mediated store (opt-in):** set `MW_API_URL` so the MCP tools read and write the same relational state the server holds through its REST API instead of a local file. The default `MW_DATA_DIR` JSONL path is unchanged.

The Next.js app surfaces that relational state as REST endpoints (also consumed by the MCP HTTP store):

- `GET/POST /api/nodes`, `/api/edges`, `/api/ceremonies`
- `GET/PATCH/DELETE /api/nodes/{id}`, `GET /api/nodes/{id}/web` (one node's neighbourhood), `GET /api/ceremonies/{id}`
- `GET/POST /api/narrative/beats`, `GET/PATCH /api/narrative/beats/{id}`, `GET/POST /api/narrative/cycles`
- `GET/POST /api/charts`, `/api/mmots`
- `GET/POST /api/diary`, `GET/DELETE /api/diary/{id}`
- `GET/POST /api/captures` (alias `/api/recordings`), `/api/inquiry-weaves`, `/api/plan-perspectives`
- `GET /api/directions`, `/api/health`, `/api/resources`
- `GET/POST /api/mcp` — StreamableHTTP MCP endpoint

**Honcho projection (opt-in):** a server started with `HONCHO_URL` projects every stored beat, ceremony and diary entry into Honcho in the background, on write. `GET /api/health` reports `honcho.enabled`. A projection never delays the wheel's response, and a Honcho that is down is a line on stderr, not an error to the writer.

## Key Concepts

- **Four Directions**: East (vision/Waabinong), South (growth/Zhaawanong), West (reflection/Epangishmok), North (wisdom/Kiiwedinong)
- **Wilson's Three R's**: Respect, Reciprocity, Responsibility — scored 0–1 per relation
- **OCAP®**: Ownership, Control, Access, Possession — Indigenous data sovereignty
- **Structural Tension**: Germination → Assimilation → Completion creative cycle
- **Ceremonial Inquiry**: opening → council → integration → closure phase progression
- **Orientation**: the question asked before an instrument is chosen — a named prior state is a fire (gap analysis); no prior state is a creating act (structural tension)
