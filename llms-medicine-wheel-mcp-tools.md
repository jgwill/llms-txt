## MCP Server & HTTP API

The `@medicine-wheel/mcp` package exposes 85 tools over two transports:

- **stdio** — `npx @medicine-wheel/mcp` (default; local JSONL store under `.mw/store/`)
- **StreamableHTTP** — `POST /api/mcp` on the running app, JSON-RPC 2.0 with `tools/list` and `tools/call`

Tool families: orientation (3 — the routing question asked before any problem-solving, listed first because list order is scan order), Four Directions (13), validators (4 — Wilson paradigm, OCAP® compliance, Two-Eyed Seeing bridge, accountability), integrations (11) and discovery (11) over nodes/edges/ceremonies/beats/cycles, structural tension (12 — charts, action steps, MMOT), ceremony lifecycle (4), epistemic (2), coordination (3 — fire-keeper status, relational check-back, gate enforcement), governance and transformation (3), reasoning observability (2), inquiry-weaves (3), plan-perspectives (3), infrastructure (7 — hosts, tenants, services, port conflicts, metis holds), and Honcho memory (4 — status, project, recall, project back).

**Server-mediated store (opt-in):** set `MW_API_URL` so the MCP tools read and write the same relational state the server holds through its REST API instead of a local file. The default `MW_DATA_DIR` JSONL path is unchanged.

The Next.js app surfaces that relational state as REST endpoints (also consumed by the MCP HTTP store):

- `GET/POST /api/nodes`, `/api/edges`, `/api/ceremonies`
- `GET/PATCH/DELETE /api/nodes/{id}`, `GET /api/nodes/{id}/web` (one node's neighbourhood), `GET /api/ceremonies/{id}`
- `GET/POST /api/narrative/beats`, `GET/PATCH /api/narrative/beats/{id}`, `GET/POST /api/narrative/cycles`
- `GET/POST /api/charts`, `/api/mmots`
- `GET/POST /api/diary`, `GET/DELETE /api/diary/{id}`
- `GET/POST /api/captures` (alias `/api/recordings`), `/api/inquiry-weaves`, `/api/plan-perspectives`
- `GET /api/directions`, `/api/health`, `/api/resources`
- `GET/POST /api/mcp` — StreamableHTTP MCP endpoint

**Honcho projection (opt-in):** a server started with `HONCHO_URL` projects every stored beat, ceremony and diary entry into Honcho in the background, on write. `GET /api/health` reports `honcho.enabled`. A projection never delays the wheel's response, and a Honcho that is down is a line on stderr, not an error to the writer.

## MCP Server (@medicine-wheel/mcp)

```bash
npx @medicine-wheel/mcp        # stdio transport
```

### Overview

The Model Context Protocol server exposes **85 tools** that let an agent conduct Indigenous-paradigm research through the Medicine Wheel — over two transports:

-   **stdio** — default; persists to a local JSONL store under `.mw/store/`
-   **StreamableHTTP** — `POST /api/mcp` on the running app, JSON-RPC 2.0 (`tools/list`, `tools/call`), dispatched against the same tool registry as stdio

### Tool families (85 total)

-   **Orientation** (3): `orient_before_solving`, `open_gap_analysis`, `check_emitted_outcome` — the question asked before an instrument is chosen. Registered first because list order is scan order, and the routing question belongs ahead of the tools it routes to
-   **Four Directions** (13): East (3) vision/spirit/new-relation · South (3) growth/mentorship/embodied-data · West (3) reflection/emotional/strawberry-teaching · North (4) wisdom/elder-council/spirit-feeding/story-archiving
-   **Validators** (4): `wilson_paradigm_checker`, `ocap_compliance_checker`, `two_eyed_seeing_bridge`, `accountability_validator`
-   **Discovery** (11) & **Integrations** (11): node/edge/ceremony/beat/cycle search, relational web, cross-system bridges
-   **Structural Tension** (12): charts, action steps, telescoping, MMOT (creator moment of truth)
-   **Ceremony Lifecycle** (4): `mw_ceremony_open`, `mw_ceremony_close`, `mw_get_direction`, `mw_store_memory`
-   **Inquiry Weaves** (3): relate artefacts and episodes, author episode-to-episode lineage edges, enumerate the chronicle catalog
-   **Plan Perspectives** (3): read and register plan/insight perspectives across the relational web
-   **Coordination** (3): `mw_fire_keeper_status`, `mw_relational_check_back`, `mw_enforce_gate`
-   **Infrastructure** (7): `register_host`, `register_tenant`, `register_service`, `detect_port_conflicts`, `hold_metis`, `reconcile_infra_state`, `list_infra_topology` — a service is registered as a `knowledge` node carrying `metadata.kind: "service"`, never as a new node type
-   **Honcho memory** (4): `honcho_status`, `honcho_project`, `honcho_recall`, `honcho_project_back`
-   **Epistemic** (2), **Governance/Transformation** (3), **Reasoning Observability** (2)

### Server-mediated store (opt-in)

Set `MW_API_URL` to make the tools read and write the live relational state the app holds through its REST API, instead of a local JSONL file. The default `MW_DATA_DIR` JSONL behavior is preserved — the HTTP store is purely additive.

### App REST API (consumed by the MCP HTTP store)

-   `GET/POST /api/nodes` · `GET/PATCH/DELETE /api/nodes/{id}` · `GET /api/nodes/{id}/web` (one node's neighbourhood, scoped and honest about what it withheld)
-   `GET/POST/PATCH/DELETE /api/edges`
-   `GET/POST /api/ceremonies` · `GET /api/ceremonies/{id}`
-   `GET/POST /api/narrative/beats` · `GET/PATCH /api/narrative/beats/{id}` (witnessing) · `GET/POST /api/narrative/cycles`
-   `GET/POST /api/charts`, `/api/mmots`
-   `GET/POST /api/diary` · `GET/DELETE /api/diary/{id}`
-   `GET/POST /api/captures` (alias `/api/recordings`), `/api/inquiry-weaves`, `/api/plan-perspectives`
-   `GET /api/directions`, `/api/health`, `/api/resources`
-   `GET/POST /api/mcp` — StreamableHTTP MCP endpoint

Read routes page honestly: a response carries `count`, `total`, `matched` and `truncated` rather than silently cutting the list.

### Honcho projection (opt-in)

A server started with `HONCHO_URL` projects every stored beat, ceremony and diary entry into Honcho on write, in the background. `GET /api/health` reports `honcho.enabled`. See Package 29.
